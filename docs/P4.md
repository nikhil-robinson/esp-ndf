# ESP32-P4 port

Branch `feature/p4`. Build any application for the P4 with `make SOC=esp32p4` (objects in `build-esp32p4/`). Layout rule: code
used by both chips lives in one place (`components/lib`, `components/include`: one file, `#if SOC_CPU_RISCV` where
the chips differ); chip-specific code lives apart (`soc/esp32s3` vs `soc/esp32p4`, `arch/xtensa` vs `arch/riscv`, S3
drivers in `drivers/<x>/*.c`, P4 drivers in `drivers/<x>/esp32p4/`). S3-specific files are not touched by the P4 work;
the S3 binaries are byte-identical. `arch/riscv/xtensa.h` lets shared code that includes `xtensa.h` build for RISC-V. Reference: ESP-IDF **v6.1** (`~/esp-idf-v6.1`, tools in `~/.espressif-v6.1`),
silicon **v3.x** (`register/hw_ver3`). Same public API as the S3: every header in `components/include` is shared; only
the CPU layer (`components/arch/riscv`), the chip layer (`components/soc/esp32p4`) and the drivers under
`components/drivers/<x>/esp32p4/` are P4 code. Chip defaults (400 MHz, UART0 console on GPIO37/38) come from
`soc/esp32p4/soc_caps.h`, so `ndf_config.h` options keep their names.

**Status: builds, not yet run on hardware.** Nothing below has been measured; the board comes later.

## What is there

| Layer | Files | Notes |
|---|---|---|
| Build | `make/project.mk`, `soc/*/soc.mk` | `SOC=` selects arch, toolchain (riscv32-esp-elf 15.2), flags, driver set, flash address (0x2000 on the P4). `tools/build_all.py SOC=esp32p4` builds every app for the P4 |
| CPU | `arch/riscv/` | `start.S` (both cores, CLIC mode, panic stack in `mscratch`), `vectors.S` (CLIC-vectored entry: 16 caller-saved registers + mepc/mcause/mstatus, FPU off in handlers, hardware nesting; exception frame on the panic stack), `irq.c` (32 programmable-level lines per core, levels 1-7, `irq_naked` = the CLIC jumps straight into the handler), `coop_switch.S`, `cpu.h` (`ccount` = mcycle, `irq_lock` = CLIC threshold 5 so level 6-7 stay open like the S3's NMI) |
| Chip | `soc/esp32p4/` | `link.ld.in` (ROM-loaded code + data in 0x4FF80000-0x4FFBCFC0; .bss, stacks and heap below in 0x4FF20000-0x4FF80000 after the L2 cache is set to 128 KB in `start.S`), `sys.c` (watchdogs off, core 1 start through LP_SYS boot address + PMU stall code, faults with RISC-V register dump), `clk.c` (PMU / DCDC voltage from eFuse calibration, CPLL 400 MHz, CPU 400 / MEM 200 / APB 100, peripheral gates), `system.c` (reset cause, restart), `time.c` (SYSTIMER: same block as the S3), `rtcclk.c` (RC_SLOW nominal) |
| Drivers | `drivers/{console,gpio,uart,gptimer,wdt}/esp32p4/` | console (UART0 / USB-Serial-JTAG), GPIO 0-54 + matrix + pin interrupts + dedicated GPIO (CSR 0x803-0x805), UART0-4 (XTAL clocked, interrupt rings), GP timers (XTAL), MWDT / LP WDT / super WDT |
| Lib | `components/lib`, `components/include` (shared files) | RISC-V branches next to the Xtensa ones: soft double without the Xtensa funnel shifter, `fmadd.s` / `fsqrt.s` / `fdiv.s`, `fence` barriers, LR/SC spinlock (`xcore.h`), libgcc helpers (`__clzsi2`, `__ctzsi2`, `__popcountsi2`) |

Builds for the P4: `arch/riscv/test_apps/irq_latency`, `wdt_test`, `libc_test`, `libm_test`, `lib_unit`,
`core_test`, `fastmath_test`, `dsp_lib`, `nn_lib`, `cpp_test`, `sysinfo`. IDF twin: `bench/idf_p4_irq` (same
interrupt-latency measurement, IDF v6.1, 400 MHz).

## Board bring-up order

Each step only after the previous one works; a dark board = stop (`docs` rule: no unrecoverable tests).

1. `examples/system/sysinfo`: banner on UART0 at 115200. First check that the ROM loads the image at 0x2000 and that
   `start.S` + the L2 cache write survive (if not: JTAG halt, read `mcause` / `mepc`).
2. Clocks: `NDF_CPU_MHZ=40` first (no PMU / CPLL), then 400; compare `ccount` against SYSTIMER over 1 s.
3. `irq_latency`: CLIC lines and the matrix path; compare with `bench/idf_p4_irq` on the same board.
4. Core 1 (`cpu1_start`), `wdt_test`, `uart_unit`, `gptimer_unit`, the lib tests.

## Unverified assumptions (check first on the board)

| Assumption | From | If wrong |
|---|---|---|
| The v3 ROM leaves 0x4FF80000-0x4FFBCFC0 free while it loads | IDF v3 bootloader sits at 0x4FFAxxxx-0x4FFBCFC0; ROM data above | image overwrites ROM state: move `ROM_LO` up or add an own loader |
| L2 cache size = one-hot write to CACHE+0x278, no invalidate needed | rev0 ROM `Cache_Set_L2_Cache_Mode` disassembly (no v3 ROM ELF in esp-rom-elfs 20241011) | stacks in 0x4FF20000+ corrupt: keep .bss in the ROM window |
| `mtvt` alignment 256 is enough; SHV entries take a plain function address | CLIC spec, IDF `_mtvt_table` (64-byte aligned) | stray vectors: check `mtvt` on the board |
| CLIC byte layout IP/IE/ATTR/CTL, CTL = level << 5 | rev0 ROM `esprv_intc_int_*` disassembly | wrong priorities |
| Core 1 boot address register LP_SYS + 0x164 | ROM `ets_set_appcpu_boot_addr` (rev0) | core 1 stays in the ROM |
