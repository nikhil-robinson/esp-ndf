# ESP32-P4 port

Branch `feature/p4`. Build any application for the P4 with `make SOC=esp32p4` (objects in `build-esp32p4/`).
Reference: ESP-IDF **v6.1** (`~/esp-idf-v6.1`, tools in `~/.espressif-v6.1`), silicon **v3.x** (`register/hw_ver3`).

**Status: everything below builds; none of it has run on hardware yet** (the board comes later). Nothing is measured.

## Layout rule

- Code both chips use lives in one file (`components/lib`, `components/include`, the shared drivers), with `#if SOC_CPU_RISCV`
  or a per-chip value (base address, interrupt source, matrix signal) where they differ. The public headers in
  `components/include` are the same for the S3 and the P4.
- Chip-specific code is separate: `soc/esp32s3` vs `soc/esp32p4`, `arch/xtensa` vs `arch/riscv`, S3 drivers in
  `drivers/<x>/*.c` vs P4 drivers in `drivers/<x>/esp32p4/*.c`.
- Shared code includes `cpu.h` (`arch/xtensa/cpu.h` or `arch/riscv/cpu.h`: `ccount`, `core_id`, `irq_lock`,
  `cpu_wait_for_irq`, `cpu_barrier`), never another architecture's header. S3-specific files are untouched.
- `soc/esp32p4/soc.mk` lists which shared driver files the P4 builds (`SOC_DRIVER_SRCS`); chip values come from
  `soc/esp32p4/soc.h` and `soc_caps.h`.
- Check used for every shared edit: the S3 object code of the edited file is identical (and `tools/build_all.py` builds the
  S3 tree: 137 of 138, `rf_pkt` fails on the base tree too, RAM limit).

## What exists

| Area | Where | P4 notes |
|---|---|---|
| Build | `make/project.mk`, `soc/*/soc.mk` | `SOC=` selects toolchain (riscv32-esp-elf 15.2), flags (no Zcmp, IDF DIG-661), drivers, image address 0x2000. `tools/build_all.py SOC=esp32p4` builds every app. `BOOT_FAST=1` adds the loader (below); `XIP=lib\|all` runs libraries / app from flash |
| CPU, interrupts | `arch/riscv/` | CLIC-vectored entry (16 caller-saved registers + mepc/mcause/mstatus, FPU off in handlers, hardware nesting), 32 programmable-level lines per core (levels 1-7), naked handlers, `irq_lock` = CLIC threshold 5, `coop_switch`, trap frame on a per-core panic stack. `NDF_TCM_IRQ=1` puts `irq_entry` in the 8 KB TCM (copied at boot) |
| Debug | `arch/riscv/debug.c`, `unwind.c`, `drivers/trace/esp32p4` | data watchpoints on the trigger module (3 per core; one-shot, the access then completes), cycle / instret counters, exact panic backtraces from a table derived from the code (`tools/mkunwind_rv.py`, appended to the image), app trace over the semihosting control block (OpenOCD `esp apptrace`), stack guard on the ASSIST_DEBUG SP monitor |
| Boot, clocks | `soc/esp32p4/{start,sys,clk}` | L2 cache set to 128 KB in `start.S` (so .bss and stacks live in 0x4FF20000-0x4FF80000), watchdogs off, core 1 start (LP_SYS boot address + PMU stall code), PMU / DCDC voltage from eFuse calibration, CPLL 400 MHz, CPU 400 / MEM 200 / APB 100 |
| Flash, XIP, PSRAM | `soc/esp32p4/cache.c`, `drivers/psram/esp32p4`, `drivers/flash/esp32p4` | flash commands on SPI1; XIP: 1 MB code window at 0x43F00000 (flash MMU entries 1008-1023, 64 KB pages) through the L1 I/D caches and the L2 cache, cache switches are ROM calls (`esp32p4.rom.ld`); HEX PSRAM (16 / 32 MB) at 0x48000000: LDO channel 2, MPLL 320 MHz, MR0/MR4/MR8, AXI path of MSPI2, PSRAM MMU, 80 MHz (200 / 250 MHz need DQS / delay-line tuning: not written). `psram_sleep_enter/exit` for light sleep |
| Loader, OTA | `soc/esp32p4/loader/`, `drivers/storage/ota.c` | `BOOT_FAST=1`: the ROM loads a 2 KB loader from 0x2000 into the top of the ROM window, it picks factory / `ota_N` from the ESP-IDF otadata, checks header, segment ranges and the appended SHA-256, copies the segments and jumps (rollback as the S3 loader). The note for the app is at `SOC_OTA_NOTE` (LP RAM). Apps end below `SOC_LOADER_BASE` in that mode |
| Chip layer | `soc/esp32p4/` | `system.c` (reset cause, restart, `sys_info` from eFuse), `cache.c`, `rtcclk.c` (RC_SLOW nominal), `stackguard.c`, `memprot.c` (RISC-V PMP: code RX, data RW, entries locked until reset), `brownout.c` (LP_ANA_PERI mode 0), `sleep.c` + `pmu_img.h`, `ulp.c` (LP core), `regi2c.h`, peripheral clock / reset gates |
| Sleep, PM, ULP | `soc/esp32p4/{sleep,ulp}.c`, `soc/esp32s3/pm.c` (shared) | light sleep (nothing powered down; PLLs off, CPU on the crystal, PSRAM safe), deep sleep (HP top, CPU, crystal, RC_FAST off; wake = reset), wake by LP timer or EXT1 (LP IO 0-7; EXT0 maps onto EXT1); the PMU words come from `tools/p4_pmu/gen.c`, which runs IDF's own PMU code on the host (`pmu_img.h`, regenerate with `tools/p4_pmu/gen.sh`); `RTC_DATA_ATTR` lives in LP RAM (initial values travel after `.data`, copied on every start except a deep-sleep wake); LP core as the ULP (`ulp_load` / `ulp_run`, one-shot LP timer re-armed by the program), `pm_lock` frequencies 400 / 200 / 100 |
| Shared with the S3 (one file) | `soc/esp32s3/{time,efuse,pm}.c`, `drivers/{crypto,storage,pcnt,mcpwm,rmt,i2c,spi,sdm,twai,xcore,lcd,usb}`, `lib/*` | per-chip bases, signals and clock set-up inside the file |
| P4 only | `drivers/{console,gpio (+rtcio),uart,gptimer,wdt,gdma,ledc,flash,tsens,i2s,adc,touch,psram,trace,dma2d,dw_gdma,ppa,jpeg,lcd (dsi, csi, isp)}/esp32p4/`, `lib/esp32p4/{dsp,nn}_pie.S` | see below |

P4-only drivers (the register layout differs from the S3 block):

- **console**: UART0 or USB-Serial-JTAG, polled. **gpio**: pads 0-54, matrix, pin interrupts, dedicated GPIO (CSR 0x803-0x805);
  **rtcio**: LP IO 0-15, hold. **uart**: UART0-4 on XTAL, interrupt rings, RTS/CTS flow control, RS485 (+ collision
  detect), IrDA, AT-pattern detection, DMA through UHCI0. **gptimer**: TIMG, XTAL source. **wdt**: MWDT, LP WDT, super WDT.
- **gdma**: AHB-DMA (3 ch) + AXI-DMA (3 ch). `gdma_alloc` returns a handle; `gdma_connect` binds it to a free channel on the
  controller the peripheral is wired to. Starts write back / invalidate the L1 D-cache over buffers and descriptors.
- **ledc**: P4 timer register, hardware gamma fade (16 ranges, no interrupt).
- **flash**: SPI1 user commands (read 0x0B, page program, erase 4 KB / 64 KB / chip, 4-byte addresses), no quad reads, no
  auto-suspend. The storage stack (NVS incl. encrypted, FAT, SPIFFS, wear levelling, OTA) runs on it.
- **tsens**, **i2s**, **adc** (one-shot, continuous, filters, monitors), **touch** (v3 sensor): see the driver headers.
- **USB**: the shared DWC2 device driver (`drivers/usb/usb_dev.c`) on the HS controller and the internal UTMI PHY: high
  speed, 512-byte bulk packets, device qualifier, 64-byte-aligned DMA buffers with cache maintenance; CDC, MSC, HID and the
  composite as on the S3. Own pads: USB Serial/JTAG stays up, no guard watchdog.

Application matrix (`tools/build_all.py SOC=esp32p4`, 138 apps): **92 build**, 49 do not: the radio ones (BLE, Wi-Fi, RF, lwIP / net / TLS tests: the P4 has no radio) and the S3-only tests written in Xtensa assembly (`CCOMPARE`, `memw`, PIE registers, the PSRAM+RF capture, the S3 IO_MUX ADC test). S3 check after this work: 1933 S3 SDK objects of ten apps compared (disassembly) with the pre-port commit f95a5c7 are identical except `spi.c` (a compiler-numbered constant symbol only).

### Vector unit (PIE) and the media / accelerator blocks

- **PIE (Xespv2p2)**: `lib/esp32p4/dsp_pie.S` (dot, dot2, saturating add, copy / set / unaligned copy, int16 add / multiply with shift,
  matrix multiply on the 64-bit QACC lanes, unaligned dot, decimating FIR core, radix-2 FFT stage) and `nn_pie.S` (int8 dot, conv row with
  requantisation, depthwise on the 16 x 32-bit QACC lanes, FC, pooling, ReLU6, add by tables) have the contracts of the S3 kernels
  (`SOC_CPU_HAS_PIE` 1, `SOC_DSP_F32_ASM` 0: the float kernels are compiler code). The unit is switched on per core in `sys.c`;
  interrupt handlers must not use it and `memcpy` never does on RISC-V. Host check: `tools/p4_pie/run.sh` runs the very ELF in
  unicorn with each `esp.*` instruction modelled from the TRM text; kernels equal integer references and `nn.c` with PIE equals `nn.c`
  without on conv / depthwise / FC / pooling / add / ReLU6.
- **Register headers** are generated from IDF's v6.1 register files by `tools/p4_regs/gen.py` into `soc/esp32p4/regs/` (offsets and
  field positions only); `regs/p4reg.h` has the `FSET / FCLR / FPUT / FGET / FV` helpers.
- `dma2d.h` (2D-DMA, 4 TX + 3 RX), `ppa.h` (scale / rotate / mirror, blend, fill), `jpeg.h` (baseline encoder), `dw_gdma.h` (DW-GDMA,
  link lists and contiguous blocks), `dsi.h` (D-PHY PLL, DCS commands, DPI video from a frame buffer; LDO channel 3 at 2.5 V),
  `csi.h` (CSI-2 capture to memory), `isp.h` (core pipeline: demosaic, CCM, colour, YUV). Test apps: `dma2d_p4`, `ppa_p4`, `jpeg_p4`,
  `dw_gdma_p4`, `dsi_p4`, `csi_p4`.

## Board bring-up order

Each step only after the previous one works; a dark board = stop (no unrecoverable tests).

1. `examples/system/sysinfo`: banner on UART0 at 115200 (revision, MAC, flash id from SPI1). Check first that the ROM
   loads the image at 0x2000 and that `start.S` + the L2 cache write survive (if not: JTAG halt, read `mcause` / `mepc`).
2. Clocks: `NDF_CPU_MHZ=40` first (no PMU / CPLL), then 400; compare `ccount` against SYSTIMER over 1 s.
3. `arch/riscv/test_apps/irq_latency`, then `bench/idf_p4_irq` on the same board; `watch_test`.
4. Core 1 (`cpu1_start`, `xcore_*`), `wdt_test`-class tests, `gptimer_unit`, `uart_unit`, lib tests.
5. Flash: `flash_test` (read), then `storage_unit`. Then enable `NDF_STACK_GUARD=256`.
6. Peripherals: `pcnt_unit` + `mcpwm_unit`, `ledc_unit`, `rmt_unit`, `i2c_unit`, `spi_unit`, `gdma_unit` (DMA: check the cache
   maintenance first), crypto tests, `adc_p4`, i2s / twai / touch / lcd-cam.
7. Memory: `psram_p4` (size, pattern, copy), then `XIP=lib` (`xip_test`), then `BOOT_FAST=1` with `ota_test`.
8. USB: `examples/usb/usb_cdc` on the HS pads (a host on the HS port; the debug USB-JTAG is unaffected).
9. Power last, each only with the supply measured and a recovery path (JTAG halt + `program_esp`): `memprot_test`, `bod_test`,
   `pm_test`, `sleep_light_test`, `sleep_test`, `ulp_test`.

## Unverified assumptions (check first on the board)

| Assumption | From | If wrong |
|---|---|---|
| The v3 ROM leaves 0x4FF80000-0x4FFBCFC0 free while it loads | IDF v3 bootloader memory map | image overwrites ROM state: move `ROM_LO` or add an own loader |
| L2 cache size = one-hot write to CACHE+0x278 / 0x27C, no invalidate needed | rev0 ROM `Cache_Set_L2_Cache_Mode` disassembly (no v3 ROM ELF in esp-rom-elfs 20241011) | stacks in 0x4FF20000+ corrupt: keep .bss in the ROM window |
| CLIC byte layout IP/IE/ATTR/CTL, CTL = level << 5; `mtvt` 256-byte aligned | rev0 ROM `esprv_intc_int_*` disassembly, CLIC spec | wrong priorities / stray vectors |
| Core 1 boot address at LP_SYS + 0x164, stall code 0x86 / 0xFF in PMU CPU_SW_STALL | ROM `ets_set_appcpu_boot_addr`, IDF `cpu_utility_ll` | core 1 stays in the ROM |
| L2MEM is cacheable by the L1 D-cache after the ROM (PMA entry 15) | IDF `cpu_region_protect.c` | harmless: the cache operations then do nothing useful; DMA buffers should be 64-byte aligned |
| PLL_F160M / PLL_F80M / SPLL are running for MCPWM / LEDC / RMT / SPI function clocks | IDF clock sources | those peripherals tick at the wrong rate: select XTAL |
| SPI1 clock left by the ROM is usable for flash commands; SPI0 left in a usable read mode for XIP | S3 driver does the same | set the clock / read mode in `flash.c` / `cache.c` |
| `INT_RAW` fade-end bit covers the whole 16-range LEDC fade | IDF ledc fade flow | `ledc_fade_busy` returns early: poll the duty readback |
| The ROM cache functions (`Cache_Enable_*`, `Cache_Invalidate_*`, `Cache_WriteBack_All`) sit at the esp32p4.rom.ld addresses on v3 and `esp_rom_spiflash_*` / `esp_rom_spi_cmd_*` too | `esp32p4.rom.ld` / `.eco0_4.ld` agree on all of them | wrong calls at XIP init, PSRAM mode registers, the loader |
| PSRAM: 80 MHz needs no tuning, LDO channel 2 at 1.8 V powers it (EV-board wiring; `NDF_PSRAM_LDO_CHAN` 0 skips it) | IDF `esp_psram_impl_ap_hex.c`, Kconfig.ldo | `psram_init` returns 0 or fails the 0x5A6B7C8D read-back |
| PMP: the ROM leaves entries 0-4 unlocked; granularity 128 B | IDF `cpu_region_protect.c` | `memprot_init` has no effect (locked entries ignore the write) |
| LP-core ULP boots straight into the program at LP RAM + 0x80; deep sleep needs RTC_PERIPH / flash supply left on (as chosen in `gen.c`) | IDF `lp_core.c`, `pmu_sleep.c` | no ULP run / the wake does not return |
| USB HS: UTMI 16-bit, turnaround 5, SUSPENDM set by software | IDF `usb_utmi_hal`, `usb_dwc_ll` | no enumeration |
| 2D-DMA / PPA / JPEG / DW-GDMA / DSI / CSI / ISP register sequences | IDF v6.1 `*_ll.h` and drivers, TRM chapters 6-8, 37-43 | frames do not move, the link does not lock, wrong colours: compare with IDF's twin on the same board |
| Brownout threshold levels 5 / 6 / 7 = 2.42 / 2.52 / 2.60 V; the clock-glitch enable bit | IDF Kconfig.power; TRM block (IDF has a TODO) | detector trips at another voltage |

## Not applicable to the P4

Radio code (BLE, Wi-Fi, RF, lwIP / net tests built on them: the P4 has no radio), the ULP-FSM (`ulp_fsm_run` returns -1: the P4
has only the LP RISC-V core), EXT0 as a separate wake source (it is EXT1), S3-only assembly / `CCOMPARE` / `memw` / `waiti`
tests (the P4 has `arch/riscv/test_apps/{irq_latency,watch_test}`), the S3 RTC warm-boot stage (`rtcboot_test`: every P4 reset
goes through the ROM), and the Xesppie SIMD kernels: the DSP / NN library runs on its C paths (`SOC_CPU_HAS_PIE` 0); the PIE
instruction set is accepted by the toolchain (`-march=..._xespv`) but kernels without a board to check them against the C
results are not shipped.
