# ESP32-P4 port

Branch `feature/p4`. Build any application for the P4 with `make SOC=esp32p4` (objects in `build-esp32p4/`).
Reference: ESP-IDF **v6.1** (`~/esp-idf-v6.1`, tools in `~/.espressif-v6.1`), silicon **v3.x** (`register/hw_ver3`).

**Status: everything below builds; none of it has run on hardware yet** (the board comes later). Nothing is measured.

## Layout rule

- Code both chips use lives in one file (`components/lib`, `components/include`, the shared drivers), with `#if SOC_CPU_RISCV`
  or a per-chip value (base address, interrupt source, matrix signal) where they differ. The public headers in
  `components/include` are the same for the S3 and the P4.
- Chip-specific code is separate: `soc/esp32s3` vs `soc/esp32p4`, `arch/xtensa` vs `arch/riscv`, S3 drivers in
  `drivers/<x>/*.c` vs P4 drivers in `drivers/<x>/esp32p4/*.c`.
- Shared code includes `cpu.h` (`arch/xtensa/cpu.h` or `arch/riscv/cpu.h`: `ccount`, `core_id`, `irq_lock`,
  `cpu_wait_for_irq`, `cpu_barrier`), never another architecture's header. S3-specific files are untouched.
- `soc/esp32p4/soc.mk` lists which shared driver files the P4 builds (`SOC_DRIVER_SRCS`); chip values come from
  `soc/esp32p4/soc.h` and `soc_caps.h`.
- Check used for every shared edit: the S3 object code of the edited file is identical (and `tools/build_all.py` builds the
  S3 tree: 137 of 138, `rf_pkt` fails on the base tree too, RAM limit).

## What exists

| Area | Where | P4 notes |
|---|---|---|
| Build | `make/project.mk`, `soc/*/soc.mk` | `SOC=` selects toolchain (riscv32-esp-elf 15.2), flags (no Zcmp, IDF DIG-661), drivers, image address 0x2000. `tools/build_all.py SOC=esp32p4` builds every app |
| CPU, interrupts | `arch/riscv/` | CLIC-vectored entry (16 caller-saved registers + mepc/mcause/mstatus, FPU off in handlers, hardware nesting), 32 programmable-level lines per core (levels 1-7), naked handlers, `irq_lock` = CLIC threshold 5, `coop_switch`, trap frame on a per-core panic stack |
| Boot, clocks | `soc/esp32p4/{start,sys,clk}` | L2 cache set to 128 KB in `start.S` (so .bss and stacks live in 0x4FF20000-0x4FF80000), watchdogs off, core 1 start (LP_SYS boot address + PMU stall code), PMU / DCDC voltage from eFuse calibration, CPLL 400 MHz, CPU 400 / MEM 200 / APB 100 |
| Chip layer | `soc/esp32p4/` | `system.c` (reset cause, restart, `sys_info` from eFuse), `cache.c` (DMA cache maintenance, XIP stubs), `rtcclk.c` (RC_SLOW nominal), `stackguard.c` (ASSIST_DEBUG SP monitor; off by default, `NDF_STACK_GUARD=256` arms it), `regi2c.h`, peripheral clock / reset gates for all ported peripherals |
| Shared with the S3 (one file) | `soc/esp32s3/{time,efuse}.c`, `drivers/{crypto,storage (not ota),pcnt,mcpwm,rmt,i2c,spi,sdm,xcore}`, `lib/*` | per-chip bases, signals and clock set-up inside the file |
| P4 only | `drivers/{console,gpio,uart,gptimer,wdt,gdma,ledc,flash,tsens}/esp32p4/` | see below |

P4-only drivers (the register layout differs from the S3 block):

- **console**: UART0 or USB-Serial-JTAG, polled. **gpio**: pads 0-54, matrix, pin interrupts, dedicated GPIO (CSR 0x803-0x805).
  **uart**: UART0-4 on XTAL, interrupt rings (RS485 / IrDA / pattern / flow control / DMA return -1: not ported).
  **gptimer**: TIMG, XTAL source. **wdt**: MWDT, LP WDT, super WDT.
- **gdma**: AHB-DMA (3 ch) + AXI-DMA (3 ch). `gdma_alloc` returns a handle; `gdma_connect` binds it to a free channel on the
  controller the peripheral is wired to. Starts write back / invalidate the L1 D-cache over buffers and descriptors.
- **ledc**: P4 timer register, hardware gamma fade (16 ranges, no interrupt).
- **flash**: SPI1 user commands (read 0x0B, page program, erase 4 KB / 64 KB / chip, 4-byte addresses), no XIP, no quad
  reads, no auto-suspend. The storage stack (NVS incl. encrypted, FAT, SPIFFS, wear levelling) runs on it.
- **tsens**: LP_TSENS with the S3's conversion and eFuse trim.

Application matrix (`tools/build_all.py SOC=esp32p4`, 138 apps): **65 build**, 73 do not: 37 need a radio (BLE, Wi-Fi, RF,
lwIP / net tests; the P4 has none), 10 are S3-only assembly / CCOMPARE / PIE tests, 26 need a driver not ported yet (below).
The 65 include `uart_unit`, `gptimer_unit`, `ledc_unit`, `pcnt_unit`, `mcpwm_unit`, `rmt_unit`, `i2c_unit`, `spi_unit`,
`gdma_unit`, `storage_unit`, `sdm_unit`, `tsens_test`, the `xcore_*` tests without assembly, the crypto tests, all lib tests
(`libc`, `libm`, `fastmath`, `dsp_lib`, `nn_lib`, `cpp_test`, `core_test`, `lib_unit`), `tests/{runtime_test,stress}`,
`examples/system/{bench,sysinfo}` and `arch/riscv/test_apps/irq_latency`. IDF twin: `bench/idf_p4_irq` (same measurement, IDF v6.1).

## Not ported (why)

| Item | Reason |
|---|---|
| PSRAM, XIP / flash cache + MMU, own boot loader | MSPI PSRAM (HEX, 200 MHz, DLL tuning) and the v3 MMU need board iteration; until then code + data must fit the 244 KB the ROM loads |
| I2S, ADC, TWAI, touch, LCD/CAM, USB OTG | different or much larger register sets than the S3 (I2S clock dividers moved to HP_SYS_CLKRST; TWAI-FD; ADC2; DWC2 HS PHY); I read the P4 clock fields but did not write blind drivers |
| Sleep, PM, ULP, brownout, memprot, RTC IO, RTC_DATA_ATTR | S3 RTC_CNTL / SENS based; P4 uses PMU + LP subsystem, and the ROM does not load LP RAM |
| BLE, Wi-Fi, RF, lwIP/net tests that need a radio | the P4 has no radio |
| OTA | needs the P4 boot path |
| Exact unwinding, watchpoints, app trace | stack scan only; RISC-V trigger module and the TRAX replacement are not written |
| TCM interrupt entry, Xesppie DSP / NN kernels | C paths run; TCM needs the loader to place code |
| S3-only tests (asm, CCOMPARE, PIE, `memw`, `waiti`) | stay S3-only; the P4 has `arch/riscv/test_apps/irq_latency` |

## Board bring-up order

Each step only after the previous one works; a dark board = stop (no unrecoverable tests).

1. `examples/system/sysinfo`: banner on UART0 at 115200 (revision, MAC, flash id from SPI1). Check first that the ROM
   loads the image at 0x2000 and that `start.S` + the L2 cache write survive (if not: JTAG halt, read `mcause` / `mepc`).
2. Clocks: `NDF_CPU_MHZ=40` first (no PMU / CPLL), then 400; compare `ccount` against SYSTIMER over 1 s.
3. `arch/riscv/test_apps/irq_latency`, then `bench/idf_p4_irq` on the same board.
4. Core 1 (`cpu1_start`, `xcore_*`), `wdt_test`-class tests, `gptimer_unit`, `uart_unit`, lib tests.
5. Flash: `flash_test` (read), then `storage_unit`. Then enable `NDF_STACK_GUARD=256`.
6. Peripherals: `pcnt_unit` + `mcpwm_unit`, `ledc_unit`, `rmt_unit`, `i2c_unit`, `spi_unit`, `gdma_unit` (DMA: check the cache
   maintenance first), crypto tests.

## Unverified assumptions (check first on the board)

| Assumption | From | If wrong |
|---|---|---|
| The v3 ROM leaves 0x4FF80000-0x4FFBCFC0 free while it loads | IDF v3 bootloader memory map | image overwrites ROM state: move `ROM_LO` or add an own loader |
| L2 cache size = one-hot write to CACHE+0x278 / 0x27C, no invalidate needed | rev0 ROM `Cache_Set_L2_Cache_Mode` disassembly (no v3 ROM ELF in esp-rom-elfs 20241011) | stacks in 0x4FF20000+ corrupt: keep .bss in the ROM window |
| CLIC byte layout IP/IE/ATTR/CTL, CTL = level << 5; `mtvt` 256-byte aligned | rev0 ROM `esprv_intc_int_*` disassembly, CLIC spec | wrong priorities / stray vectors |
| Core 1 boot address at LP_SYS + 0x164, stall code 0x86 / 0xFF in PMU CPU_SW_STALL | ROM `ets_set_appcpu_boot_addr`, IDF `cpu_utility_ll` | core 1 stays in the ROM |
| L2MEM is cacheable by the L1 D-cache after the ROM (PMA entry 15) | IDF `cpu_region_protect.c` | harmless: the cache operations then do nothing useful; DMA buffers should be 64-byte aligned |
| PLL_F160M / PLL_F80M / SPLL are running for MCPWM / LEDC / RMT / SPI function clocks | IDF clock sources | those peripherals tick at the wrong rate: select XTAL |
| SPI1 clock left by the ROM is usable for flash commands | S3 driver does the same | set the clock in `flash.c` |
| `INT_RAW` fade-end bit covers the whole 16-range LEDC fade | IDF ledc fade flow | `ledc_fade_busy` returns early: poll the duty readback |
