# Wireless (BLE GATT, Wi-Fi STA/AP, lwIP, HTTP/HTTPS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** esp-ndf talks BLE (GATT server and client), Wi-Fi (station and access point, open and WPA2-PSK), IP (lwIP: ARP, DHCP, ICMP, UDP, TCP, DNS) and HTTP/HTTPS from its own CALL0 code, proven against ESP-IDF running on the second board.

**Architecture:** esp-ndf runs on the DEVKIT; the BOX-3 runs one ESP-IDF "peer" image driven by line commands over its USB-JTAG console (`bench/idf_wl_peer`), so every feature has an IDF counterpart on the same air. Radio below the MAC already exists (`rf_wifi.c` raw frames, `ble_hw.c` link layer); new code is host-side: a BLE ATT/GATT layer on `ble_hw`, an 802.11 MLME + WPA2 + CCMP on a rewritten `rf_wifi` ring, vendored lwIP (NO_SYS=1) with a Wi-Fi netif, then HTTP and TLS. New code lives in optional components an app lists in `COMPONENTS`, so no existing app grows.

**Tech Stack:** C (CALL0, -fstack-protector-strong), esp-ndf drivers (sha, aes, p256, x25519, rng, coop), lwIP 2.x from the IDF tree, ESP-IDF v5.3.5 NimBLE + esp_wifi on the peer, Python 3 host scripts, `tools/ndf_test.py`.

**Spec:** the user's brief (2026-10-27): GATTS, GATTC, STA, AP, lwIP on esp-ndf, ESP-IDF on the other board as the counterpart, CALL0 only, no windowed code; memory `wireless-plan.md` (v1 = own GATTS/GATTC, Wi-Fi STA+AP, lwIP, UDP/TCP, HTTP(S), no eFuse features).

## Global Constraints

- Everything in esp-ndf is CALL0 and our own code. **No IDF blob, no windowed-ABI code, no `libphy`/`libnet80211` in esp-ndf.** IDF runs only on the BOX-3 peer. (A windowed option may exist later behind menuconfig; not in this plan.)
- Boards: DEVKIT `...24:58:7C:E2:C9:D0-if00` = esp-ndf; BOX-3 `...30:30:F9:5A:C1:10-if00` = IDF peer. Address by by-id path; check the port before every run; halt-on-panic; no reboot loops (recover over JTAG, `tools/gdb.sh`).
- No eFuse burns, no secure boot / flash encryption / HMAC / DS / XTS.
- Every driver gets an ESP-IDF twin measured on the same board before it counts as done; speed numbers go into `docs/PERFORMANCE.md` (vs IDF, with headroom to the floor). Target: faster than IDF, never slower.
- Configurable (`NDF_*` options, `tools/ndfconfig/schema.py`) and portable (capability flags in `soc_caps.h`, no S3 assumptions outside `components/drivers/rf` and `components/soc`).
- Security: parsers bounds-checked and fuzzed on the host (pattern: `tools/fuzz`), secrets wiped (`explicit_bzero`), constant-time compares, MIC/replay checks before any state change. New findings go to `docs/security/AUDIT_FINDINGS_*.md`.
- Test data and captures go in `bench/*/data` and are committed. RF work uses plain engineering wording (bench bring-up, low TX power index, boards adjacent).
- Wi-Fi v1: 2.4 GHz, 20 MHz, 802.11b/g basic rates (1 and 6 Mbit/s first, raise later), open + WPA2-PSK (CCMP). No WPA3, no HT/VHT, no power save, no WPS, no enterprise.
- BLE v1: LE 1M, legacy advertising, ATT MTU 23 until LL data-length is verified, no pairing/encryption.

## Review Focus

- Oversized, truncated or self-contradicting ATT/L2CAP PDUs (length fields past the buffer, handle 0, start > end): expected an ATT error response or silent drop, never a crash or a read past a table.
- 802.11 frames with bad lengths, IE lengths past the frame, oversize SSIDs, deauth/disassoc floods and frames from other BSSIDs: dropped, no state change, bounded work per frame.
- Forged or replayed EAPOL-Key frames (wrong MIC, old replay counter, message 3 with a different ANonce): rejected before keys are installed; a failed handshake leaves no half-installed key.
- Peer vanishing mid-procedure (BLE link loss during a read, Wi-Fi beacon loss during DHCP, TCP peer reset): timeouts fire, resources are released, the stack re-advertises / re-scans.
- Buffer exhaustion (RX ring overrun at line rate, lwIP pbuf pool empty, 10 clients on the AP): frames are dropped and counted, nothing blocks the core, a long run (soak) shows no leak.

### Task 13: TLS 1.3 and HTTPS (own implementation)
