# ESP32-P4 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** esp-ndf builds and (once a board is connected) boots on the ESP32-P4 v3.x with its own RISC-V CPU layer, P4 chip layer and the core peripheral drivers. The S3 build stays unchanged.

**Architecture:** `make SOC=esp32p4 ARCH=riscv` selects `components/arch/riscv` (entry, CLIC trap/interrupt entry, `irq_*`, `coop_switch`, fault + unwinder) and `components/soc/esp32p4` (link script, boot, clocks, cache/MMU, systimer, reset cause). Each SoC lists the driver folders it supports in `soc.mk`; P4 drivers are new `.c` files next to the S3 ones (`<drv>_p4.c`), selected by that list, so the public headers in `components/include` stay the same.

**Tech Stack:** C11 + RV32 assembly, riscv32-esp-elf GCC 15.2 (`~/.espressif-v6.1`), esptool `--chip esp32p4`. Reference: ESP-IDF v6.1 at `~/esp-idf-v6.1` (`register/hw_ver3`, `riscv/`, `hal/esp32p4`, `esp_system/ld/esp32p4`).

**Spec:** the user's request of 2026-11-05 ("port esp-ndf to the ESP32-P4, full thing end to end, code only, branch feature/p4, faster than IDF, hardest to easiest") plus `docs/PORTING.md` (layering) and the project rules in memory: all-own code (no ROM calls, no IDF code), read the reference first, every driver gets an IDF twin, measured wins go to `docs/PERFORMANCE.md`, never burn eFuses, nothing unrecoverable.

## Global Constraints

- Target silicon: ESP32-P4 **v3.x** (IDF v6.1 default min rev 3.01, max 3.99). `hw_ver3` register headers only.
- CPU flags: `-march=rv32imafc_zicsr_zifencei_zaamo_zalrsc -mabi=ilp32f`; no `zcmp` (IDF `SOC_CPU_ZCMP_WORKAROUND`, interrupt bug DIG-661). PIE / hardware-loop assembly only in files built with `_xesploop_xespv`.
- Image: flash offset **0x2000** (P4 ROM reads the first image there), `esptool.py --chip esp32p4 elf2image`.
- ROM-loaded segments only inside `[0x4FF80000, 0x4FFBCFC0)` (ROM data starts at 0x4FFBCFC0 on v3; the low L2MEM may be L2 cache while the ROM runs). Everything outside that window is filled by our own code after boot.
- CLIC: base 0x20800000, ctrl 0x20801000 + 4·(16 + n), NLBITS 3, standard `mintthresh` CSR 0x347 on v3, external interrupt n = CLIC id 16 + n, interrupt matrix core0 `DR_REG_INTR_BASE`, core1 +0x800.
- Cycle counter: `mcycle` (P4 has no `SOC_CPU_HAS_CSR_PC`). Core id: `mhartid`.
- S3 regression: `python3 tools/build_all.py` (S3) must stay green after every task.
- No ROM function calls, no eFuse writes, no flash writes outside our own partitions.

## Review Focus

- Interrupt arriving during `irq_lock()` on the other core / nested at a higher CLIC level: the frame must restore `mepc`/`mcause`/`mintthresh` exactly; pinned by `p4_irq_frame` (offset asserts on the frame struct vs the asm).
- FPU used in an ISR: must fault loudly (mstatus.FS = Off inside handlers) as on the S3; pinned by a link-time check that `irq_entry` clears FS.
- Image segment outside the ROM-safe window: build must fail, not boot-loop; pinned by an `ASSERT` in `link.ld.in`.
- A driver folder without a P4 implementation silently compiled for P4: must not be built; pinned by `soc.mk` driver list + a build of `irq_latency` for P4 that links no S3-only object (`nm` check).
- S3 builds broken by the shared build-system change: pinned by `tools/build_all.py` after each task.

## Order

Prerequisites first (nothing compiles without Task 1), then hardest to easiest as the user asked. Ruling: build system is placed first although it is not the hardest — every other task's test is "it builds for P4".

### Task 2: RISC-V trap + CLIC interrupt layer (hardest)

**Files:** Create `components/arch/riscv/{riscv.h,start.S,vectors.S,irq.c,coop_switch.S,unwind.c,unwind.h,debug.c}`, `components/soc/esp32p4/soc_intr.h`.

**Interfaces — Produces:** same API as `xtensa.h`/`irq.h`: `ccount()`, `core_id()`, `irq_lock()/irq_unlock(uint32_t)/irq_enable_all()`, `irq_attach(src, level 1..5, fn, arg)`, `irq_detach`, `irq_install(cpu_int, fn, arg)`, `irq_attach_nmi`, `irq_naked(src, level, handler)`, `coop_switch(save, load)` (ra, sp, s0-s11 = 14 words), `ndf_fault(...)` called with the trap frame.

- [ ] CLIC vectored mode (`mtvec` mode 3, `mtvt` = per-core table in TCM `0x30100000`): each external interrupt vectors straight to a stub that saves only caller-saved regs (ra, t0-t6, a0-a7 = 16 words + mepc/mcause), calls the C handler from a table, restores. Levels 1..5 map to CLIC level byte `NLBITS_TO_BYTE(level)`; `irq_lock` = swap `mintthresh` to level 5 (NMI-equivalent level 7 stays open), not `mstatus.MIE`, so naked level-5+ handlers keep running.
- [ ] `irq_naked`: SHV-vectored entry straight into the user's assembly handler (no frame) — the latency floor, replaces the Xtensa fast path.
- [ ] Exceptions (non-vectored `mcause` < 16 path): full frame, `ndf_fault(kind, mcause, mepc, mtval, frame, sp)`; backtrace by stack scan as on S3 (frame pointers off) — `unwind.c` decodes `jal`/`jalr` return sites.
- [ ] Inside handlers `mstatus.FS` = Off (float use traps), restored on exit.
- [ ] Check: `make SOC=esp32p4` of `components/arch/test_apps/irq_latency` links; `objdump` shows the vector table and stubs at 0x3010xxxx; `_Static_assert`s on frame offsets. Commit.

### Task 3: Boot, both cores, clocks

**Files:** Create `components/soc/esp32p4/{soc.h,soc_caps.h,link.ld.in,sys.c,clk.c,system.c,time.c,cache.c}`.

**Interfaces — Produces:** `sys_start0/1` (called from `start.S`), `sys_cpu_hz()`, `delay_us/ms`, `time_us/time_ticks/systimer_lo` (SYSTIMER @ `DR_REG_SYSTIMER_BASE`, 16 MHz), `cpu1_start(fn)`, `sys_reset_cause/_str`, `periph_enable/periph_reset` (HP_SYS_CLKRST).

- [ ] Link script: ROM-loaded `.iram.text/.data/.rodata` in `[0x4FF80000,0x4FFBCFC0)` with `ASSERT`; `.bss`, stacks and heap may extend below 0x4FF80000 down to 0x4FF20000 (above a 128 KB L2 cache) only after `cache.c` set the L2 size to 128 KB — `sys_start0` does that before zeroing `.bss`.
- [ ] Disable TIMG0/1 and LP (RTC) WDT and feed/disable the super WDT as IDF `bootloader_init` does (read `bootloader_support/src/esp32p4/bootloader_esp32p4.c` first).
- [ ] CPU clock: CPLL to 360 MHz (v3 default; 400 MHz if IDF v6.1 allows it for v3) following `esp_hw_support/port/esp32p4/rtc_clk.c` register writes, not its ROM calls.
- [ ] Core 1: release from reset/stall via HP_SYS_CLKRST + boot address register as IDF `esp_system/port/cpu_start.c` (`start_other_core`) — registers only.
- [ ] Check: P4 build of a `hello` test app links; `nm` shows no ROM symbols. Commit.
